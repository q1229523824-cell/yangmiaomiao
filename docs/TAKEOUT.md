# 外卖点单参考：营养模型与内容边界

更新时间：2026-09-12；适用版本：0.3.0。

## 使用目的

帮助用户提前安排早餐、午餐、晚餐，在每餐内选择自己做或外卖，确定份量并复制搜索词与点单要求。共 12 种本地组合，其中 3 种用于早餐；不是商家名录。“沙县”只是搜索及菜式示例，不代表连锁品牌统一营养或卫生背书，不作“干净外卖认证”。

## 估算如何得到

每个模板公开食材在既有 `data/catalog.ts` 中的称重口径、生重/干重等价份量区间、额外用油和调料碳水区间。逐项以每100克营养乘以份量，额外油按9千卡/克、调料碳水按4千卡/克计入；分别累加下界/上界，再向外取整。具体结果可运行 `npx vite-node scripts/preview-takeout.ts` 查看。

这是一组点单情景估算，不是实际外卖称重或品牌营养表。熟重仅帮助点单，米饭吸水、肉类失水、带骨比例和商家做法都会造成误差；没有固定通用的生熟换算保证。实际额外用油/调料可能超出假设上界，不能把区间当成置信区间或检测结果。普通一只鸡腿配一整盒米饭，不等同于“小饭加肉去皮”的示例。

个人单餐条件默认取当前档案每日热量/蛋白目标的早餐 25%、午餐 35%、晚餐 30%，只是软件筛选分配，不代表完整日摄入处方。首页使用这一默认目标，兼容旧外卖页仍可手动调整。筛选用热量上界 ≤ 上限、蛋白下界 ≥ 下限同时成立，同时展示碳水与脂肪；不宣称全部营养素达标，不把低热量视为充分健康条件。没有匹配时明确提示，不静默改阈值。

## 忌口与记录

已知主食材与潜在调料中的排除项参与硬过滤，分类、收藏或重新打开不绕过过滤。有任何过敏记录时暂停个性推荐；模板无法证明店铺实际配料和交叉接触安全。点单备注中的“不放”不是商家已确认。

首页“这餐吃这个”把模板 ID、名字、点单文本、份量假设和营养区间保存到当日 `Meal.diningByMemberId`。它是计划，不表示已购买、已吃或实际达到营养目标。

- 计划合计按每人每餐的来源计算：自炊用食材克数，外卖用已选快照区间，同一餐不重复计入。
- 选择外卖但没选搭配，或旧搭配不满足新禁忌时，明确标记待选；营养概览只显示已选部分，不伪装成完整日摄入。
- 原自炊食材留作切回时恢复；购物清单不采购外卖餐所对应成员的食材，仍保留另一位自炊成员和加餐的份量。
- 新禁忌每次读取和点击保存/复制时重检，失效方案不显示也不能复制。档案目标变化则保留原选择并提示核对，不自动替换。
- v0.2 独立页面和 `AppState.takeout.selections` 仅用于旧入口兼容；旧“点单参考”不会自动转成日计划，也不加入新计划营养。

## 内容参考（一般点餐原则，非套餐数值来源）

- [香港卫生防护中心：健康烹调方法](https://www.chp.gov.hk/tc/static/90039.html)：支持去皮瘦肉、少油烹调、减少含盐/糖调料与搭配蔬菜。
- [香港卫生防护中心：健康中菜](https://www.chp.gov.hk/tc/static/90051.html)：支持按人数食量点餐，兼顾蔬菜和谷物，少油盐、酱汁另放。
- [世界卫生组织：健康饮食](https://www.who.int/initiatives/behealthy/healthy-diet)：饮食多样性及减少盐、糖等的一般原则。

这些来源支持内容方向，没有提供本目录某份鸡腿饭或麻辣烫的营养数值。目录不保存在线来源到运行时，也不在设备上请求这些网站。

## 验证与维护

`tests/takeout.test.ts` 覆盖目录、目标、严格上下界、禁忌、过敏、无结果与排序；旧外卖状态/页面测试保留兼容性覆盖。`tests/meal-planning.test.ts` 和 `tests/meal-planning-page.test.ts` 增加三餐、跨日期复用、双人成员吃法、营养/购物联动、失效点击、失败恢复、schema 4 迁移、完整备份及 60 份混合计划容量测试。`scripts/verify-simulator.ts` 验证日期选择器、三餐原生按钮、混合购物、重新打开及禁忌更新；网络 API 故障注入仍不等于手机飞行模式。
