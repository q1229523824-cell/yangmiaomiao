# 双人家常健身饮食助手

一个原生 TypeScript 微信小程序：提前安排两个人每天的早餐、午餐和晚餐，每餐可分别选择自己做或外卖。自炊共用菜谱、按档案计算不同克数，计划、偏好、购物清单和历史都保存在本机。

源码包含离线核心、原生手机页面，以及类型、单元、官方模板编译和模拟器分层验证入口。真实 AppID 已配置；当前验收进度与运行证据见 [PROGRESS.md](PROGRESS.md)，正式发布准备见 [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md)。测试、体验版和审核后的正式版分别记录，不以其中一项代替其他验收。

## 已实现

- 首页三餐各自提供“自己做 / 外卖”，不必跳到另一个页面；两位成员可以分别选择不同吃法。
- 支持今天至未来第 14 天排餐，快捷日期条展示一周，日期选择器可选更远日期；选择后自动保存，切回日期恢复原安排。
- 内置 12 种本地点单组合（含 3 种早餐），展示营养估算区间和具体份量，支持收藏、复制点单建议及修改已选搭配。
- 编辑两位成员的称呼、身高、体重、年龄、活动量和目标强度。
- 首页提供档案入口并明确预填数据只是示例；档案页使用底部固定保存栏、数字键盘、逐字段错误及首个错误成员定位，支持长称呼和小屏换行。
- 为自炊生成共同的三餐及可选加餐，个人克数不同；切到外卖保留原自炊食材，切回来无需重新随机。
- 保存当前菜单；重新打开、切换页面或跨过零点都不会自动换菜。
- 用离线规则理解“不要番茄”“不要鱼，想吃猪里脊”等表达；对“不过敏”、减量、故障描述和不支持的复合词保守反馈，不把误识别写成偏好。
- 将明确禁忌作为硬约束；无可用方案时显式报错，不偷偷放回禁忌食材。
- 将“牛奶过敏/海鲜过敏”等明确表述记录为过敏原过滤限制；只有明确输入“取消某某过敏”才会解除，普通偏好重置不会解除。六种已建模过敏原组合都有安全失败或可生成的明确结果。
- 存在过敏原过滤记录时隐藏调味建议，并对普通燕麦、荞麦面按麸质风险保守过滤；包装配料和交叉污染仍需人工核对。
- 单独移除偏好或重置普通偏好，过敏原资料不会被普通重置清除。
- 从同一个不可变计划快照汇总实际选择的自炊/外卖营养，避免重复计算；购物只统计自炊成员的食材。外卖未选好时明确显示“待选”，不会把部分热量当成完整一天。
- 本地保存最多 60 份历史菜单，并在确认后恢复菜单及当时的普通偏好；当前过敏原过滤记录不会被历史覆盖。
- 对超出本地模板表达能力的热量目标或极端单份明确停止生成；这属于软件能力门禁，不是医学建议。
- 遇到个别菜谱组合的份量或热量不匹配时，在同一随机种子下最多尝试 64 个确定性候选；硬禁忌始终保留，候选耗尽才提示调整。
- 提供加载、空状态、保存失败提示、本地数据清除和缓存版本迁移；已有但损坏/未来版本的缓存不会被默认数据静默覆盖。
- 所有页面共用本地事务队列；排餐、偏好、档案、购物勾选和历史恢复基于最新已保存状态更新，避免快速切换页面时互相覆盖。
- 档案页提供可选的本地备份/恢复：把最近一次已保存状态复制到剪贴板，换设备时手动粘贴恢复；备份校验格式、版本和完整性，不经过服务器。

## 提前安排三餐（0.3.0）

在“今日”页依次选择 **日期 → 成员 → 每餐的自己做 / 外卖**。例如提前把明天安排成“早餐自己做、午餐外卖、晚餐自己做”，再切到另一位成员安排；两人不必一致。

选外卖后，直接在这一餐里点“这餐吃这个”，选择会自动保存。选好后收起候选列表，点“更换搭配 / 查看点单要求”可展开修改。日期切换、重开应用、跨过零点都保留安排；只有主动换当天自炊菜谱才重算自炊，已选外卖及其他日期不被随机替换。

内置酸奶燕麦鸡蛋早餐、无糖豆浆鸡蛋早餐、沙县去皮鸡腿饭、清汤自选麻辣烫、清蒸鱼饭等组合。默认按当前档案每日目标的早餐 25%、午餐 35%、晚餐 30% 分配筛选参考，热量不是越低越好。每项标明具体份量、做法、热量和三大营养素区间；这些是组合估算，不是商家实测营养，也不证明某店卫生。模型及来源见 [外卖估算说明](docs/TAKEOUT.md)。

- 热量区间上界不超过上限、蛋白质区间下界不低于下限，才列为“符合条件”；未达标项单列差异，不能记录为本餐匹配推荐。
- 食材及可能含有该食材的调料继续参与忌口筛选；没有结果不放宽限制。有任何过敏记录时暂停个性化外卖推荐，因为离线资料无法核验商家配料及交叉接触。
- 已选外卖存入对应日期、成员、餐次的计划快照，营养合计使用它的估算区间替代该成员这餐的自炊营养，不代表实际已经吃过。改回自炊会恢复原食材和购物份量。
- 修改吃法产生新快照，购物勾选重新开始，避免增加采购份量后误以为已买齐。历史仍保留旧版本；最多 60 份，优先保留今天和未来各日期最新安排。
- 新增禁忌后，不合条件的已选外卖标记“待重新选择”，停止显示/复制旧方案，不会偷偷换菜。新目标不再匹配已选组合时提示核对。
- 只有主动点“复制”才写入剪贴板。复制搜索词后到外卖平台搜索，下单和商家确认由用户完成；本功能没有定位、店铺检索、自动下单或价格数据。
- 本地 schema 升级为 4，兼容旧 v1/v2/v3 存储与备份，保留原档案、菜单和购物勾选。旧版独立外卖页和参考记录仅为兼容旧入口而保留，不再作为首页主入口；旧参考不会擅自转换成已选餐。完整备份包含新排餐、最多 50 项收藏及最多 60 条旧参考。

## 离线边界

“离线”指小程序代码包已经下载到设备后，下列核心业务不发送网络请求：档案编辑、营养估算、偏好解析、提前排餐、外卖组合筛选、购物清单、历史查看与恢复。源码中没有后端地址、模型调用、遥测或广告 SDK。真实外卖平台搜索和下单仍需用户自行联网完成。

导入微信开发者工具时选择“不使用云服务”即可；当前版本不需要开通云开发环境或配置云函数。AppID 只用于识别小程序项目、编译、预览和后续上传。

以下事情仍需要网络或平台能力：

- 首次获取及更新小程序代码包；
- 登录微信开发者工具、上传代码、生成体验版和提交审核；
- 微信清理本地数据后的重新获取；
- 尚未实现的跨设备同步或真实大模型能力。

两台手机当前不会自动同步，卸载小程序或清理微信存储可能丢失本地资料。完整说明见 [PRIVACY.md](PRIVACY.md)。

为降低离线设备迁移风险，档案页可在用户主动点击后复制一份 JSON 备份文本到剪贴板，也可从剪贴板校验后恢复。备份包含身体数据和饮食记录，只应粘贴到自己信任的位置；它不是云备份，也不会自动同步。

## 本地验证

要求 Node.js 22 和 npm。

```powershell
npm ci
npm run verify
npm run verify:all
npm run preview:plan
```

`npm run verify` 依次运行 TypeScript 类型检查和全部 Vitest 测试；`verify:all` 再追加微信官方 WXML/WXSS 编译器检查；`preview:plan` 在终端生成一份可复现的示例菜单。测试数量和结果以本次命令输出及对应提交的验收记录为准。

0.3.0 验收（2026-09-12）：`npm run verify:all` 通过 357 项测试及 5 WXML / 6 WXSS 编译；新版原生模拟器 22/22 通过，原数据恢复且无应用异常，证据见 [PROGRESS.md](PROGRESS.md)。剪贴板采用隔离模拟，网络采用 API 故障注入，不能替代真实手机回归。`npm run preview:takeout` 可查看 12 种组合和两位成员三餐的实际计算结果。

2026-09-08 的验收结果：切换到新 AppID `wxc4ab98745c2f2533` 后，`npm run verify:all` 通过（21 个测试文件、262 项测试；4 个 WXML、5 个 WXSS）；此前账号的微信开发者工具模拟器 `npm run verify:simulator` 16 项核心交互全部通过，原模拟器存储已恢复且未捕获应用异常。新账号 `0.1.2` 已上传并设置为体验版，体验二维码已展示；手机飞行模式、触控和新体验成员扫码仍需真机记录。

Windows 上安装微信开发者工具后，还可以运行官方 WXML/WXSS 编译器检查：

```powershell
npm run verify:wechat
```

若脚本没有自动找到安装目录，可临时指定：

```powershell
$env:WECHAT_DEVTOOLS_PATH = "微信开发者工具安装目录"
npm run verify:wechat
```

`verify:wechat` 只检查模板和样式语法，不能替代登录后的完整项目编译、模拟器交互及真机验收。

安装并登录有此 AppID 权限的微信开发者工具、启用工具的 CLI 服务后，可单独运行原生模拟器回归：

```powershell
npm run verify:simulator
```

脚本通过开发者工具 CLI 打开当前项目的自动化模式，核对模拟器环境与 AppID 后，备份并临时替换项目键 `fitness-couple:app-state`。它验证启动与重开、偏好、档案、购物、历史和存储错误等流程；退出处理会恢复该键的原值，原本不存在则删除测试键，并校验恢复结果，不清空其他本地存储键。

每次运行的报告、截图和 `storage-backup.private.json` 写入 `artifacts/simulator/<运行时间>/`；整个 `artifacts/` 已被 Git 忽略，备份可能包含原模拟器中的个人档案，不应提交或公开。若运行中断或报告显示 `restored: false`，先保留该备份并核对恢复状态，再继续使用模拟器数据。

模拟器的离线项目使用网络 API 故障注入，让 `request`、`downloadFile`、`uploadFile` 和 `connectSocket` 拒绝调用并检查调用记录。它验证应用业务没有网络依赖，不能证明 iPhone 或 Android 在飞行模式下的微信行为。`verify:simulator` 不包含在 `verify:all` 中；脚本存在也不代表验收已通过，实际结果以报告和 [PROGRESS.md](PROGRESS.md) 为准。

## 使用方式

1. 首次进入“今日”页会用示例档案在本机生成第一份菜单。点击“填写两人档案”，核对并修改实际数据。
2. 打开或切换页面不会自动换菜；主动换菜、按新设置重算、修改饮食偏好或确认恢复历史会更新当前菜单。
3. 顶部选日期和成员，在早餐、午餐、晚餐内分别选自己做或外卖；每次选择自动保存，看到保存失败提示时需重试。加餐仍按自炊计算。
4. 在“档案”页点底部“保存档案”后，旧菜单会保留并提示主动重算；输入不合法时会标红并定位到对应成员。临时切换 Tab 会保留未保存草稿，退出前仍需保存。
5. 在“今日”页输入禁忌或偏好；它们为两位成员和所有日期共用，切日期不会恢复旧禁忌。重复设置同一偏好不会无谓重生成。“少放番茄”会明确提示按“不放番茄”处理，明确过敏记录需同样明确地解除。
6. “购物”页只统计当前所选日期的自炊食材；“历史”可查看旧版本。全部数据只保存在当前设备，如需换设备，在“档案”页手动备份迁移。

## 项目结构

```text
miniprogram/
├─ pages/          # 今日排餐、购物、档案、历史，以及兼容旧入口的外卖页
├─ data/           # 本地食材、菜谱与默认档案
├─ domain/         # 营养、偏好、排餐、快照校验和购物清单
├─ repositories/   # 带版本校验和串行事务队列的微信本地存储
├─ services/       # 日期排餐、按餐吃法、菜单生命周期与历史恢复
└─ presentation/   # 领域对象到 WXML 展示模型的转换
scripts/           # 终端预览、官方编译器检查和原生模拟器回归
tests/             # 领域、页面控制器、状态生命周期、存储和结构回归测试
```

详细设计和数据流见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 重要限制

- 营养数据是常见食材的近似值，调味料、品牌差异和实际烹饪损耗可能造成偏差。
- 过敏原过滤只覆盖目录中结构化记录的食材，并在有过滤记录时隐藏调味建议；包装配料、品牌差异和交叉污染仍需自行核对，不能把本工具当作过敏安全保证。
- 这是日常健身饮食辅助工具，不提供医疗诊断、疾病治疗或个体化临床营养建议。
- “离线饮食小助手”是确定性规则解析器，不是真实大模型。
- 当前没有账号、云备份、夫妻双设备同步、支付或订阅消息。

原始单文件 HTML 仅作为产品需求和初始数据参考，不是运行时依赖，也不应提交含个人临时目录信息的原文件。
