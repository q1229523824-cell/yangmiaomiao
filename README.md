# 双人家常健身饮食助手

一个原生 TypeScript 微信小程序：两个人吃同一套家常菜，程序根据各自档案计算不同克数，并在本机保存菜单、偏好、购物清单和历史快照。

当前源码的离线核心、类型检查、自动化测试及官方 WXML/WXSS 编译器检查已完成。登录态完整项目编译、模拟器、真机断网和体验版发布仍待真实 AppID 与用户账号参与，不能把模板编译或本地测试通过等同于已经发布。

## 已实现

- 编辑两位成员的称呼、身高、体重、年龄、活动量和目标强度。
- 生成一份共同的早餐、午餐、晚餐及可选加餐，只让个人克数不同。
- 保存当前菜单；重新打开、切换页面或跨过零点都不会自动换菜。
- 用离线规则理解“不要番茄”“不要鱼，想吃猪里脊”等表达；对“不过敏”、减量、故障描述和不支持的复合词保守反馈，不把误识别写成偏好。
- 将明确禁忌作为硬约束；无可用方案时显式报错，不偷偷放回禁忌食材。
- 将“牛奶过敏/海鲜过敏”等明确表述记录为过敏原过滤限制；只有明确输入“取消某某过敏”才会解除，普通偏好重置不会解除。六种已建模过敏原组合都有安全失败或可生成的明确结果。
- 存在过敏原过滤记录时隐藏调味建议，并对普通燕麦、荞麦面按麸质风险保守过滤；包装配料和交叉污染仍需人工核对。
- 单独移除偏好或重置普通偏好，过敏原资料不会被普通重置清除。
- 从同一个不可变菜单快照计算营养汇总和双人购物清单。
- 本地保存最多 60 份历史菜单，并在确认后恢复菜单及当时的普通偏好；当前过敏原过滤记录不会被历史覆盖。
- 对超出本地模板表达能力的热量目标或极端单份明确停止生成；这属于软件能力门禁，不是医学建议。
- 提供加载、空状态、保存失败提示、本地数据清除和缓存版本迁移；已有但损坏/未来版本的缓存不会被默认数据静默覆盖。

## 离线边界

“离线”指小程序代码包已经下载到设备后，下列核心业务不发送网络请求：档案编辑、营养估算、偏好解析、排餐、购物清单、历史查看与恢复。源码中没有后端地址、模型调用、遥测或广告 SDK。

以下事情仍需要网络或平台能力：

- 首次获取及更新小程序代码包；
- 登录微信开发者工具、上传代码、生成体验版和提交审核；
- 微信清理本地数据后的重新获取；
- 尚未实现的跨设备同步或真实大模型能力。

两台手机当前不会自动同步，卸载小程序或清理微信存储可能丢失本地资料。完整说明见 [PRIVACY.md](PRIVACY.md)。

## 本地验证

要求 Node.js 22 和 npm。

```powershell
npm ci
npm run verify
npm run verify:all
npm run preview:plan
```

`npm run verify` 依次运行 TypeScript 类型检查和全部 Vitest 测试（当前 15 个文件、201 项）；`verify:all` 再追加微信官方 WXML/WXSS 编译器检查；`preview:plan` 在终端生成一份可复现的示例菜单。

Windows 上安装微信开发者工具后，还可以运行官方 WXML/WXSS 编译器检查：

```powershell
npm run verify:wechat
```

若脚本没有自动找到安装目录，可临时指定：

```powershell
$env:WECHAT_DEVTOOLS_PATH = "微信开发者工具安装目录"
npm run verify:wechat
```

当前 Windows 验收环境的微信开发者工具版本为 `2.02.2608060`，`verify:wechat` 已实际通过 4 个 WXML 和 5 个 WXSS 文件。这个结果只证明模板和样式通过官方底层编译器，不能替代登录后的完整项目编译、模拟器及真机验收。

## 导入微信开发者工具

1. 在微信公众平台注册或取得一个小程序的真实 AppID。
2. 登录微信开发者工具，选择“导入项目”，目录选择仓库根目录。
3. 将导入配置中的 AppID 换成你们自己的真实 AppID。
4. 编译后按 [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) 逐项验证。

仓库中的 `project.config.json` 故意使用 `touristappid`。它只是可公开提交的占位值，不代表真实小程序身份，也不足以完成登录态模拟器、真机预览、上传或发布验收。AppID 本身不是 AppSecret；任何 AppSecret、令牌或私钥都不得写入小程序前端或提交到仓库。

现有验收机上，开发者工具 CLI 的 `islogin` 返回未登录，使用占位配置执行 `cli open` 返回 code 10：“不存在此 AppID”。这是缺少真实 AppID 和登录态的预期阻断，不是已完成模拟器验证的证据。

## 使用方式

1. 首次进入“今日”页会在本机生成第一份菜单。
2. 后续只有点击“换一套家常菜”“按新设置重算”或确认恢复历史时才改变当前菜单。
3. 在“档案”页保存修改后，旧菜单会保留并提示主动重算。
4. 在“今日”页输入禁忌或偏好；重复设置同一偏好不会无谓重生成。“少放番茄”会明确提示当前按“不放番茄”处理，“少放辣”只会取消已有辣味优先而不会伪装成严格不辣；明确过敏记录需用“取消牛奶过敏”这类同样明确的表达解除。
5. “购物”页的勾选和“历史”页的快照都只保存在当前设备。

## 项目结构

```text
miniprogram/
├─ pages/          # 今日、购物、档案、历史四个原生页面
├─ data/           # 本地食材、菜谱与默认档案
├─ domain/         # 营养、偏好、排餐、快照校验和购物清单
├─ repositories/   # 带版本的微信本地存储
├─ services/       # 菜单生命周期与历史恢复用例
└─ presentation/   # 领域对象到 WXML 展示模型的转换
scripts/           # 终端预览及可选官方编译器检查
tests/             # 领域、页面控制器、状态生命周期、存储和结构回归测试
```

详细设计和数据流见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 重要限制

- 营养数据是常见食材的近似值，调味料、品牌差异和实际烹饪损耗可能造成偏差。
- 过敏原过滤只覆盖目录中结构化记录的食材，并在有过滤记录时隐藏调味建议；包装配料、品牌差异和交叉污染仍需自行核对，不能把本工具当作过敏安全保证。
- 这是日常健身饮食辅助工具，不提供医疗诊断、疾病治疗或个体化临床营养建议。
- “离线饮食小助手”是确定性规则解析器，不是真实大模型。
- 当前没有账号、云备份、夫妻双设备同步、支付或订阅消息。

原始单文件 HTML 仅作为产品需求和初始数据参考，不是运行时依赖，也不应提交含个人临时目录信息的原文件。
